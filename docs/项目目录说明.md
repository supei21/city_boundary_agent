# 项目目录说明

本文档规定文件应该放在哪里。新增功能时先判断其职责，再放入对应目录，避免入口、业务代码、数据和运行产物重新混在一起。

## 目录职责

| 目录 | 职责 | 典型内容 |
| --- | --- | --- |
| `backend/` | HTTP 交付层 | FastAPI 路由、请求模型、流式响应、会话工作区 |
| `boundary_agent/` | 核心业务层 | 智能体编排、工具、领域模型、规则、存储接口 |
| `boundary_agent/spatial/` | 空间数据层 | SHP读取、投影转换、地图数据和候选成果导出 |
| `frontend/` | 用户界面 | React 组件、样式、API 客户端、前端类型 |
| `config/` | 可调整配置 | 分析规则、模型默认配置、本机模型配置 |
| `data/sample/` | 演示数据 | 可复现、可共享的小型样例数据 |
| `data/input/` | 业务输入 | 本地上传或研究使用的原始属性数据 |
| `prompts/` | 提示词模板 | 决策、解释、审查等模型提示词 |
| `scripts/` | 程序入口 | Web 服务、CLI、批处理启动脚本 |
| `tests/` | 自动化验证 | 单元测试、API 测试、智能体事件流测试 |
| `runtime/logs/` | 运行日志 | API、前端程序日志 |
| `runtime/results/` | 中间结果 | JSON、SQLite 等可再生成结果 |
| `runtime/exports/` | 用户成果 | 导出的图件、报告和 SHP ZIP |
| `runtime/uploads/` | 大文件暂存 | 分块上传的 SHP ZIP，重置工作区时清理 |
| `docs/` | 当前文档 | 架构说明、使用说明、汇报材料 |

## 依赖方向

```text
frontend -> backend -> boundary_agent
                     -> config / prompts / data
```

- `boundary_agent/` 不依赖 FastAPI 或 React，便于独立测试和复用。
- `backend/` 只负责协议适配和会话状态，不重复实现分析规则。
- `frontend/` 只通过 API 使用后端，不读取 Python 运行文件。
- `scripts/` 只做启动和参数组装，不承载核心业务逻辑。

## 新文件放置规则

1. 新增分析能力时，核心实现放在 `boundary_agent/tools/` 或 `boundary_agent/workflow/`，API 只增加薄路由。
2. 新增页面组件时放在 `frontend/src/components/`，跨组件类型放在 `frontend/src/types.ts`。
3. 用户上传数据不要放在源码目录；临时数据进入运行工作区，固定研究数据放 `data/input/`。
4. 地图、报告和压缩后的 SHP 成果统一写入 `runtime/exports/`。
5. 日志、数据库和生成结果不提交版本库；需要测试的数据应缩小后放入 `data/sample/`。
6. 模型密钥只写入 `config/model_local.py` 或环境变量，不写入源码和文档。
7. 不在项目根目录新增临时脚本；可复用入口进入 `scripts/`，一次性实验放在独立分支或外部工作目录。

## 后续空间分析扩展建议

```text
boundary_agent/
├─ spatial/                 # 空间数据读取、投影与几何校验
├─ tools/                   # 面向智能体的空间分析工具封装
└─ workflow/                # 调入调出图和报告任务编排

runtime/exports/
├─ maps/                    # 地图成果
├─ reports/                 # PDF / DOCX 报告
└─ vectors/                 # GeoJSON / GeoPackage / SHP ZIP
```

等空间功能真正开始实现时再创建这些子目录，当前 Demo 不提前堆放空模块。
